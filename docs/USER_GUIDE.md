# Freshservice Knowledge Base Exporter v3.4.2 — User Guide

## 1. Purpose

This Windows PowerShell utility exports Freshservice **Solutions / Knowledge Base** articles to browsable **HTML** and structured **JSON**, with a consolidated **CSV** inventory, category and folder reference data, and execution logs.

Two inventory modes are available:

- **Automatic:** downloads the latest inventory generated by a scheduled **Analytics Data Export**.
- **Manual:** reads a local Freshservice report in **CSV** or **XLSX** format.

Both modes deduplicate article IDs and then retrieve article content individually through the Freshservice REST API.

## 2. Requirements

- Windows with **Windows PowerShell 5.1** and Windows Forms.
- Network access to the relevant Freshservice tenant.
- A Freshservice API key authorized to read the articles and associated metadata.
- For automatic mode, a scheduled **Solutions** Data Export configured for API delivery that has completed at least one run.
- For manual mode, a CSV or XLSX inventory containing an **ID** column.

Normal use does not require Windows administrator privileges. Follow your organization's security and execution policies.

## 3. Launch

Download `Freshservice-KnowledgeBase-Exporter.ps1` using **Raw → Download raw file** on GitHub. Preserve its **UTF-8 with BOM** encoding when editing it for compatibility with Windows PowerShell 5.1.

From its containing directory, execute:

```powershell
.\Freshservice-KnowledgeBase-Exporter.ps1
```

Complete the graphical form:

1. **Freshservice domain:** for example, `yourcompany.freshservice.com`.
2. **Freshservice API key:** a key belonging to an authorized account.
3. **Basic Auth password:** keep the placeholder `X`; do not enter a personal password.
4. **Inventory source:** Automatic or Manual.
5. **Export destination:** select a local or authorized network directory.
6. Click **Start export** and check the completion dialog.

## 4. Automatic Analytics inventory

Configure a scheduled export in Freshservice under **Analytics → Settings → Data Export → Create Export**.

- **Module Name:** `Solutions`.
- **Schedule:** choose the required frequency, for example `Daily`.
- **Workspace filter:** select the authorized workspace scope.
- **Basic filters:** avoid unintentionally excluding required articles.
- **Receive At:** `API`.
- **Export fields:** include `ID` at minimum. `Title`, `Type`, `Status`, `Author`, `Category`, `Folder`, and relevant date fields are useful additional metadata.

Save and activate the scheduled export, then copy its **API URL** into the application's **Analytics export URL** field.

The application retrieves the **most recently generated** Analytics file. Starting the application **does not execute the Analytics schedule immediately**. Inventory freshness is determined by the scheduled export time.

Treat the Analytics URL as sensitive, and do not publish it.

## 5. Manual inventory

Choose **Manual — select a CSV or XLSX file** and browse for a Solutions report containing an `ID` column.

The script removes invalid or duplicated identifiers, then uses the same article extraction engine as automatic mode.

## 6. Processing workflow

1. Read the manual report or download the latest Analytics inventory.
2. Identify the `ID` field and deduplicate article records.
3. Retrieve Freshservice categories and folders.
4. Call the article detail API for each unique ID.
5. Organize article exports by category and folder using available metadata.
6. Generate HTML, JSON, inventories, and logs.

Primary API endpoints:

```text
GET /api/v2/solutions/categories
GET /api/v2/solutions/folders
GET /api/v2/solutions/articles/{article_id}
```

No article-count limit is hardcoded. The export is constrained by the inventory and the API account's access permissions.

## 7. Exported files

Each run creates a timestamped export directory containing:

```text
Freshservice-KB-Report-Export-.../
├── Articles/
│   └── <Category>/
│       └── <Folder>/
│           ├── <ID>_<Title>.html
│           └── <ID>_<Title>.json
├── source-deduplicated.csv
├── categories.json
├── folders.json
├── articles-clean.csv
├── articles-complete.json
├── export.log
└── export-errors.csv      (when errors are recorded)
```

`articles-clean.xlsx` may also be created if Microsoft Excel automation is available.

Articles without resolvable category/folder IDs are still exported using fallback directory naming; the script does not invent metadata IDs.

## 8. Saved preferences

The application can remember the domain, mode, destination folder, and Analytics URL. Saving the API key is **optional**.

Configuration is stored under:

```text
%LOCALAPPDATA%\Freshservice\KnowledgeBaseExport\settings.json
```

Sensitive values are encrypted using `ConvertFrom-SecureString` with Windows user-scoped DPAPI. These settings are bound to the user's Windows environment; do not publish or transfer `settings.json`.

Disabling preference storage does not prevent a one-time export.

## 9. Error handling and troubleshooting

| Message or condition | Action |
| --- | --- |
| Missing required fields | Complete the fields listed in the dialog. |
| Schedule not run yet | Allow the first scheduled Analytics export to finish. |
| HTTP 401 / 403 | Verify credentials and access to the inventory/article. |
| Missing ID column | Check the report fields and file structure. |
| XLSX not generated | Use `articles-clean.csv`; Excel automation may be unavailable. |
| Article-level failure | Check `export-errors.csv` and `export.log`. |
| Preferences not saved | Export can continue without locally stored settings. |

To check completeness, compare the unique ID count, the number of **successful API reads**, the number of **HTML and JSON article pairs saved**, and any article-level failures. These counts are distinct: an API request may succeed even if saving the article files fails on Windows. Directory names are sanitized to remove trailing spaces and periods.

## 10. Maintenance and security

- Confirm authorization for the requested Knowledge Base scope.
- Never commit exported articles, live Analytics URLs, API keys, inventories, or local settings to a public repository.
- Preserve the `ID` export field when adjusting the Analytics schedule.
- Check the scheduled export frequency and the API account permissions.
- Repeat an export and review the logs after changes to the scheduling, source format, or code.
